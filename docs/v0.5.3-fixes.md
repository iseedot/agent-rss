# v0.5.3 修复：提示可执行性 · backfill dry-run · commit 守卫

> 基线：v0.5.2（`b8fd02c`）。修复 v0.5.2 审核发现的 3 个问题。

---

## 1. 提示指向不存在的 action

**问题**：`payload.next_steps` 写「需要更多用 `rss action=ledger` 查询」，但工具 action
只有 brief/qa/commit/fetch/unread/markread/manage/calibrate，manage op 也没有 ledger，
提示不可执行。

**修复**：
- 新增 `manage op=ledger`（`index.ts`），转发到 `rss.py ledger`，返回完整事实/观点台账；
- `next_steps` 改为「需要更多用 `rss action=manage op=ledger` 查询」；
- 工具描述与 op 校验列表同步更新。

## 2. `manage op=backfill` 缺 `--dry-run`

**修复**：`index.ts` 新增 `dry_run` 布尔参数，`op=backfill` 时透传 `--dry-run`
（CLI 原本就有）。现在工具侧也能安全预览：

```
rss {action:"manage", op:"backfill", last:2, dry_run:true}
```

## 3. commit 守卫对 `backfilled` 无效

**问题**：守卫只拒绝 `status == "committed"`。回填生成的 run 状态是 `backfilled`，
且 `slot_date` 取自文件名（可能是今天）→ 没跑 brief 直接 commit 会命中回填 run，
覆盖对应日期的报告文件（例如 `10-01_08.md`）并重复记账。

**修复**：不带 `run_id` 时改为 **`status != "briefed"` 一律拒绝**：

```
❌ Latest run is not a fresh brief
   最近一次 run 状态为 backfilled（不是 briefed）；请先执行 brief 开始新一期
   （或显式传 run_id 强制提交）
```

保留原有的「slot_date 早于昨天」检查；显式传 `run_id` 仍可强制补提（逃生舱不变）。
