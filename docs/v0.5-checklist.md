# v0.5 修改清单：目的 · 变化 · 注意事项

> **v0.5.1 已修复若干缺陷**（速览标题计入事实、markread JSON 计数、退役口径、commit 状态校验、
> jev 异常降级等），详见 `docs/v0.5.1-fixes.md`。本文保留为 v0.5.0 的变更记录。

> 对应 commit `834c443`（前一版 `381a4bf`，即真机当前钉住的版本）。
> 本文是部署/运维前的完整清单；设计与推导见 `docs/PLAN-rss-report.md`。

## 一、修改目的

1. **把定时任务从"10+ 次工具调用 + 全量原文进上下文"压缩到 3 次调用**
   每期约 200 条未读 × ~300 字原文（≈30k+ token）原本全部进主模型，且机械工作
   （抓取、去重、分类、计数、文件名、标已读、跨期对比）全压在主模型上。
   现在：`brief`（准备）→ 写草稿 → `qa`（质检+核验）→ 改稿 → `commit`（落盘+状态），
   LLM 只做两次生成。
2. **跨期状态落 SQLite 台账**（原来只读最近 1~2 篇 md）
   实现提示词的硬规则：观点只在「新增/反转/强化/削弱」时写；上期事实无新数字写「延续」；
   `待确认` 跨期不升级；两期事实不重复。
3. **用 jev 做廉价判断，用 codemode 之外的确定性代码做记账**
   jev：逐条分类（事实/观点/跳过）、主题、价值分、观点变更、事实重复、草稿逐行质检、
   核验判定。台账/计数/格式/落盘/标已读由脚本完成，不消耗主模型注意力。
4. **消除旧实现的具体缺陷**：
   - 正则解析 fetch 输出（`/New items: (\d+)/`）→ 结构化 JSON；
   - `sendUserMessage(..., {triggerTurn:false})` 非法选项导致每期无谓唤醒 → 定时逻辑整体移除；
   - `markread` 只能单条或按 tag/时间批 → `--ids` + "本批"概念；
   - 抓取串行无锁 → 并发 + flock；
   - 300 字截断看不到观点 → 观点候选给正文（默认 1200 字）；
   - 文件名/表头时区靠模型算 → 插件按 `RSS_TZ` 生成。
5. **中文质量前置**：jev 的 CJK 判断弱于英文且可能出现"低准确率+高置信度"，
   提供 `calibrate` 工具（采样→人工标注→准确率/置信度分桶→能否用于丢弃判定的结论）。
6. **凭据分层**：兼容现有自建扩展的 key 存放方式，同时保证 headless 可用。

## 二、能力变化对照

| 维度 | v0.4.1 | v0.5.0 |
|---|---|---|
| 工具 action | 11 个（add/fetch/unread/search/recent/markread/list/remove/tag/tags/stats） | 8 个（brief/qa/commit/fetch/unread/markread/manage/calibrate） |
| 每期调用 | 10+ 次 | 固定 3 次（+ 可选 calibrate） |
| 进主模型 | 全量原文文本 | 结构化 payload（facts/opinions/ledger/上期报告） |
| 跨期状态 | 无（只读 md） | SQLite 台账（事实/观点/run/state 四表） |
| 分类/对比/质检 | 全由主模型 | jev 批量分类 + 置信度门控；失败自动降级为启发式 |
| 网页核验 | 模型自觉，可能超 4 次 | qa 内 `source_check`，硬预算（默认 4） |
| 文件名/表头 | 模型自己算北京时间 | 插件按 `RSS_TZ` 生成，commit 会剥离模型给的表头并重写 |
| 标已读 | 模型调 markread（多半全标） | commit 原子标记"本期 brief 批次" |
| 插件内定时抓取 | `RSS_AUTO_FETCH_MINUTES` | **已删除**（paseo 是唯一时钟） |
| search/recent | 工具层可用 | 工具层移除（CLI `rss.py search/recent` 仍保留供调试） |

## 三、逐文件变更

### `rss.py`
- 新增 `--json` 全局输出（envelope：`{ok, action, data, error}`），所有子命令支持。
- 并发抓取（`ThreadPoolExecutor`，默认 6 worker）+ 跨进程锁 `flock`（`DB_PATH.fetch.lock`）；
  `fetch --json` 返回逐 feed 的 `{id,title,url,new,error}`。
- Schema：`rss_items` 加 11 列（`brief_run_id/kind/topic/has_number/novel/change/verify_needed/
  conf_json/triage_json/triaged_at/is_skipped`）；新增 `rss_ledger_facts`、`rss_ledger_opinions`、
  `rss_runs`（含 `report_name/prev_report/fetched_new/websearch_used/violations`）、`rss_state`。
  老库在 `init_db()` 时自动增量迁移。
- 新命令：
  - `brief`：建 run → 抓取 → 选全部未读 → 关键词预过滤（跳过项标 `is_skipped`）→ 同源去重
    （重复项立即标已读）→ 启发式 triage → 记录 `brief_run_id` → 返回 items/ledger/上期报告/session。
  - `payload`：按 run 组装 facts/opinions（读 triage_json），含 `numbers/value/flags/repeat_of/
    relation/relation_confidence`，跨源事实聚类（`dup_count/dup_sources`），
    高置信 `relation=none` 的观点直接剔除（低置信降级为 `new` + `relation_uncertain`）。
  - `annotate`：stdin JSON 数组批量回写 triage（与已有 triage_json 合并，不覆盖）。
  - `check`：stdin `{body}` → 确定性校验（汉字总数/每条字数/观点条数≤3/六字段/禁用词/链接/
    体育娱乐词/速览夹带观点），返回带行号的 violations（1-based）。
  - `commit`：stdin `{body, run_id?, strict?, websearch_used?}` → 终审 → 解析正文 →
    拼首行表头（`MM-DD hh｜本期使用 N 条（速览 x 条 + 观点 y 条）｜本次新抓取 M 条｜上期：…`）→
    原子写 `RSS_REPORT_DIR/MM-DD_hh.md`（tmp+rename）→ 更新台账（事实状态机/观点匹配更新/
    退役超期观点）→ 本期批次全部标已读 → 写 run 记录 → 返回 `reportText`。
    校验不过时不落盘（`strict:false` 可强制落盘并把违规写入 run）。
  - `ledger`：导出台账快照；`sample`：随机取样（校准用，无副作用）。
- `markread --ids 1,2,3`；`cmd_fetch` 改为返回 `(text, data)`。
- 时间：所有文件名/表头/时间戳用 `RSS_TZ`（默认 Asia/Shanghai）；资讯时间不参与过滤。

### `index.ts`（全量重写）
- `outputSchema` + `structuredContent` + `details`（codemode 可直接读对象）。
- 8 个 action；`manage` 用 `op ∈ add/remove/list/tag/tags/stats`；`calibrate` 用 `op ∈ sample/score`。
- jev 通道：
  - `runJevTriage`（brief 内）：pass1 全量 kind/topic/has_number/value；pass2 观点 relation/
    target/verify（state 里带活跃观点台账）；pass3 事实 repeat/repeat_of/new_number（state 里带上期事实）。
    批量 10 条/次、并发 4、deadline 预算、429 指数退避；`skip` 需置信度 ≥ 阈值才真丢，
    否则降级为 fact + `possible_skip`；`none` 需置信度 ≥ 阈值才剔除，否则改 `new` + `relation_uncertain`。
  - `runJevLint`（qa 内）：按行分节问 bool（叙事夹观点/情绪词/体育娱乐/缺署名/检验缺反例/趋势缺信号），
    概率 >0.6 记违规（行号与确定性检查对齐）。
  - `runVerification`（qa 内）：从草稿提取"检验/结论 = 未证实/存疑/无法判断/待确认"的观点块，
    逐条 `ctx.executeTool("source_check", {claim, fetchContent:true})` → jev 判 verdict + counter；
    硬预算 `RSS_VERIFY_BUDGET`（默认 4）；工具不存在时返回 `verification_unavailable`。
  - 全部失败路径降级为启发式，报告流程不会因 jev 而中断。
- 凭据 `resolveTypesafeKey()`：env → `<agent-dir>/rss-plugin/auth.json`（0600，组/他人可读则拒绝）
  → `TYPESAFE_KEY_FILE` 或 `~/.config/typesafe/key`；解析结果注入 `process.env.TYPESAFE_API_KEY`。
- 删除 `setInterval` 定时抓取。
- 修复 `clampInt/clampFloat`：`Number("")===0` 导致未设置的 env 全部变成 0（曾使 web 核验静默为 0 次）。

### 其他
- `package.json`：版本 0.5.0、描述更新、`check` 指向冒烟测试、`pi.prompts` 注册。
- `prompts/rss-report.md`：手动补跑用的接口约定与报告规则。
- `tests/smoke.py`：26 项端到端断言（不联网、用临时库），`npm run check` 可跑。
- `README.md` / `INSTALL.md`：按新接口重写；`docs/PLAN-rss-report.md`：设计+实现状态。

## 四、行为与语义决定（务必知悉）

1. **未读即窗口**：不做发布时间过滤；上一期 commit 成功后整批标已读，未出报告则不标 → 下期重来。
2. **标已读范围** = 本期 `brief` 选中的批次（含未被报告采用、含被 skip 的）；不是"只用到的"。
3. **去重掉的重复条目**在 `brief` 阶段即标已读（否则永远积压）。
4. **表头计数**：`x` = 普通速览行数，**不含 `延续：` 行**；`N = x + y`；`M` = 本次 fetch 新增数；
   上期 = run 记录里的文件名，无则「无」。commit 会剥离模型给的第一行表头后重写。
5. **文件名** = 北京时间 `MM-DD_hh.md`；同一小时内重复运行会覆盖同名文件（08/21 两期不会撞）。
6. **台账匹配**：事实按归一化文本精确匹配；观点按「来源 + claim 相似度 ≥0.6」匹配，匹配不到则新增。
   来源提取靠正则（`@账号` / `财新《栏目》` / `xx认为`）。
7. **观点退役**：连续 `RSS_OPINION_RETIRE_RUNS`（默认 8）期未被引用 → `retired`，不再进 brief。
8. **"待确认"不会自动关闭**：只有本期带证据再次出现（且未标待确认）才升 `confirmed`。
9. **commit 是唯一写入口**：文件、台账、已读、run 四者由它原子收尾；`strict:false` 是逃生舱。
10. **核验只针对草稿**：不核验未进报告的候选；核验来源是 `source_check`（需要 pi-web-access 或等价工具）。

## 五、部署注意事项（真机）

1. **git ref 钉死**：真机 settings 是 `git:…@381a4bf`，`pi update` 不会前移 pin。需要：
   ```bash
   pi remove git:github.com/iseedot/agent-rss@381a4bfcdf186f637a731a74b6cdfdf3c6401635
   pi install git:github.com/iseedot/agent-rss     # 或重新 pin 到 834c443
   ```
2. **key 三选一**（需要在 paseo daemon 派生 agent 的环境里可见）：
   - `TYPESAFE_API_KEY` 环境变量；
   - `<agent-dir>/rss-plugin/auth.json`，内容 `{"apiKey":"…"}` 或纯文本 key，**必须 0600**；
   - `TYPESAFE_KEY_FILE` 指向共享文件（默认回退 `~/.config/typesafe/key`）。
3. **先校准再信任丢弃判定**：
   ```
   rss {action:"calibrate", op:"sample", max:50}   # 写 calibration.json，逐行填 label
   rss {action:"calibrate", op:"score"}            # accuracy + 置信度分桶 + 是否 trustworthy
   ```
   不达标 → 提高 `RSS_JE_V_SKIP_CONF` / `RSS_JE_V_NONE_CONF`（如 0.85），宁多勿漏。
4. **定时任务提示词的「2. 执行步骤」要替换**为接口约定（`prompts/rss-report.md`，
   或 `docs/PLAN-rss-report.md` §7）；否则模型可能继续调 `unread`，浪费上下文。
5. **两条 schedule 用 `--timezone Asia/Shanghai`**；插件不看程序时间做过滤，但文件名/表头按北京。
6. **依赖**：python3 + feedparser（必须）；web 核验需 pi-web-access（可选，缺了会提示 unavailable）；
   jev 需 key（可选，缺了自动启发式降级）。
7. **首次验证**：`paseo schedule run-once <id>`，然后检查
   `RSS_REPORT_DIR` 是否有 `MM-DD_hh.md`、`rss.py ledger --json`、`rss.py stats`。
8. **迁移安全**：老库自动加列/加表；回滚到 0.4.x 也能跑（旧 SQL 不引用新列，新表被忽略）。

## 六、已知限制与风险

| # | 限制 | 缓解 |
|---|---|---|
| 1 | jev 中文准确率与置信度校准未在真机验证（最大风险） | 上线前跑 `calibrate`；不达标调高阈值 |
| 2 | 观点跨期匹配用 difflib 相似度，非语义匹配 | J2 的 `related_to_o<id>` flag 辅助；后续可换 jev 复核 |
| 3 | 来源提取靠正则，署名不规范会产生新台账条目 | 命名规范（`@账号`/`财新《栏目》`）即可 |
| 4 | `待确认` 不会自动过期，长期占用 `unconfirmed` 列表 | 人工确认或后续加过期策略 |
| 5 | 语义质检阈值固定 0.6、情绪词表有限，可能漏检 | commit 确定性红线兜底；可调问题措辞 |
| 6 | 同小时重跑覆盖同名报告 | 08/21 两期设计上不冲突；手动补跑注意 |
| 7 | `rss_runs.jev_stats` 预留未填充；`websearch_used` 靠模块内存从 qa 传到 commit | 同一 session 内有效；跨 session 提交会记 0 |
| 8 | codemode "逃生舱"脚本未内置（PLAN P4） | 插件接口本身可被 codemode 调用，按需临时写 |
| 9 | 200 条/期 jev 约 20–45 批调用，预算 150s | 可调 `RSS_JE_V_BATCH/CONCURRENCY/DEADLINE` |
