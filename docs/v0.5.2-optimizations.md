> 基线：v0.5.1（`bbad31a`）。针对 v0.5.1 审核报告里标出的三处边界做优化。

## 1. jev 用量与成本落库（可观测性）

**问题**：`rss_runs.jev_stats` 一直为空，审核只能按 batch 规则推算调用次数；
`classify()` 返回的 `usage`（tokens/cost）被丢弃，真实计费不可见。

**实现**：
- `index.ts` 在 triage / lint / verification 三处累积 `classify()` 的
  `usage`（input/output/totalTokens/cost）与调用次数、各 pass 批次数、失败数；
- 新增 `rss.py runstats`（stdin JSON，浅合并写入 `rss_runs.jev_stats`）：
  `brief` 写 `triage.*`，`qa` 写 `qa.*`，`commit` 继续写 `websearch_used`；
- 新增 `rss.py runs [--limit N] --json`：每期时长、抓取/使用条数、web 次数、
  jev 调用数、tokens、cost；工具侧可用 `manage op=runs` 触发。

```
rss {action:"manage", op:"runs", limit:10}
python3 rss.py runs --limit 20 --json
```

## 2. payload 瘦身（单次输入体积）

**问题**：v0.5.1 实测 payload ≈16k token > 旧 unread ≈12.4k token —— 整体 prompt 是
523k→82k，但这 16k 是主模型的固定输入，值得压。

**原则**：不靠砍信息量，靠「只给需要的」。

| 项 | 旧默认 | 新默认 | 说明 |
|---|---|---|---|
| `RSS_BRIEF_FACTS_MAX` | 60 | **40** | 按 value/时间排序后截断 |
| `RSS_BRIEF_FACT_CHARS` | 300（硬编码） | **200** | 新增可配 |
| `RSS_BRIEF_OPINION_TOP` | 10 | **8** | 观点候选给全文的条数 |
| `RSS_BRIEF_OPINION_CHARS` | 1200 | **800** | 观点正文截断 |
| `ledger` | 全量 80 事实 + 30 观点 | **只给被引用的** | 全部 `unconfirmed` + 被 `repeat_of` 引用的事实 + 被 `related_to_o<id>` 引用的观点 |
| `last_report` | 总是附全文 | **自动** | 台账为空（冷启动）才附全文；`RSS_BRIEF_INCLUDE_LAST_REPORT=0/1` 可强制 |
| 空字段 | 保留 | **剔除** | `_compact()` 去掉 null/空串/空数组 |

**关键点**：完整台账仍然给 jev（J2/J3 需要），只是**给模型的 payload 做引用式过滤**，
所以功能零损失。payload 里会注明「ledger 只列出被引用到的条目；需要更多用 `rss action=ledger`」。

**额外修复（基准测试暴露的真实风险）**：跨源事实聚类加了保护——
**数字冲突或主题不同的标题不合并**。例如「美联储降息25个基点」与「美联储降息50个基点」
标题相似度很高，旧逻辑会误合并丢一条，现在会保留两条。

**合成基准**（88 条、台账 80 事实/30 观点、上期报告 873 字符）：

| | 字符数 |
|---|---|
| 旧配置估算（60×300 字事实 + 10×1200 字观点 + 全量台账 + 上期全文） | 43,930 |
| v0.5.2 实测（40 事实 + 8 观点 + 引用式台账 + 不带上期全文） | **19,718** |
| v0.5.2 强制带上期全文 | 20,591 |

约 **-55%**；真机原 payload 为 33.8k 字符，预计降到 ~15–18k（≈8–9k token）。

## 3. 台账冷启动回填

**问题**：第一期台账为空，模型写的「延续：」行匹配不到 → 按设计不入库；
真机已有历史报告，却要等 8 期自然积累。

**实现**：新增 `rss.py backfill`：

```bash
python3 rss.py backfill --dry-run --last 2     # 预览：每篇 facts/continuations/opinions 条数
python3 rss.py backfill --last 2               # 回填最近 2 篇（RSS_REPORT_DIR）
python3 rss.py backfill --file ~/Chat/rss/10-01_08.md
```

- 复用现有 `_parse_report` + `_ledger_upsert_*`，与正常 commit 同一套解析/匹配逻辑；
- 每个文件建一条 `rss_runs` 记录（`status='backfilled'`，slot/slot_date 取自文件名），
  使退役窗口与 run 历史保持连贯；
- **不标记任何已读**；`--dry-run` 不写库。

回填后，下一期的 J3 重复检测、J2 观点变更、`延续` 匹配立即生效。
