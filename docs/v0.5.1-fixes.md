## 1. 修复清单

### ① 速览小节标题被当成事实【中，会改数据】

**问题**：`_parse_report` 在 facts 区把「任何非空行」都当事实，
`**国际经济与市场**`、`### 科技` 这类分组标题被计入条数并写入 `rss_ledger_facts`。
真机 `10-01_08.md` 被解析成 34 条（表头写 30 条）。

**修复**（`rss.py`）：
- 新增 `_HEADING_LINE_RE = ^(?:#{1,6}\s+\S|\*{1,2}[^*\n]{1,60}\*{1,2}\s*[:：]?$)`；
- facts 区只认 `- ` 列表行，标题只作分组，不计数、不入台账；
- opinions 区的标题行不再进入观点块（不参与 200 字统计）；
- facts 区「非列表行且非标题」的散文行由 `_validate_report` 报 `structure` 违规（不再静默丢弃）。

**效果**：真实报告回放 `10-01_08.md` 34 → 30 条（与表头一致）。

**行为变化（模型需遵守）**：速览区必须用 `- ` 列表行；`**小标题**`/`### 小标题` 仅作分组；
散文行会被 `qa`/`commit` 拒绝。

### ② `markread`（不带 ids）在 `--json` 下丢计数【低-中，误导】

**问题**：`cmd_markread` 返回纯字符串 → JSON 信封 `data=null` → 工具回报 “Marked 0 item(s)”。

**修复**：所有返回路径改为 `(text, {"marked": n})`；JSON 信封统一新增 `text` 字段；
`index.ts` 优先使用信封 `text`。

### ③ `relation=none` 丢弃阈值硬编码 0.7【低，与文档不符】

**修复**：Python 侧改用 `_env_float("RSS_JE_V_NONE_CONF", 0.7)`，与 TS 侧一致；
调低阈值也生效，直接用 CLI/annotate 写入的 relation 同样受控。

### ④ 台账 `signal` / `time_window` 写入整段趋势【低，语义错】

**修复**：新增 `_split_trend()`：从「趋势」解析「验证信号」（`验证信号为X` / `信号：X` 等）
与「时间窗」（`两周内` / `3天` / `一个月` 等），解析不到留空；三列不再同值。

### ⑤ 观点退役按 run 数而不是按「期」【低】

**问题**：`last_seen_run < run_id - N`；同一期的 brief 重试会加速退役。

**修复**：按 `(slot_date, slot)` 去重后的最近 N 期构造 run 窗口，
`last_seen_run NOT IN (窗口)` 才退役。配置项 `RSS_OPINION_RETIRE_RUNS`（默认 8 期）。

### ⑥ `commit` 不校验 run 状态【提示，防误覆盖】

**问题**：不带 `run_id` 时取「最近一次 run」；若它已提交或来自旧期，
会覆盖上一期报告并重复记账。

**修复**：不带 `run_id` 时——最近 run 已 `committed`，或 `slot_date` 早于昨天 → 拒绝提交，
提示先跑 `brief`；显式传 `run_id` 仍可强制补提。CLI 新增 `--run` / `--no-strict`。

### ⑦ 死代码清理【提示】

- `rss_state` 表：建了从不读写 → 从 `SCHEMAS` 删除（老库保留空表，无副作用）。
- `rss_items.novel` / `conf_json`：从未读写 → 从迁移列表删除。
- `verify_needed` 保留（payload 会带给模型作提示）。

### ⑧ 环境变量读取【附】

新增 `_env_int()` / `_env_float()`：空值/非法值回退默认值（不再变成 0 或抛异常），
用于 `RSS_BRIEF_MAX`、`RSS_BRIEF_FACTS_MAX`、`RSS_BRIEF_OPINION_TOP`、
`RSS_BRIEF_OPINION_CHARS`、`RSS_OPINION_RETIRE_RUNS`、`RSS_JE_V_NONE_CONF`。

### ⑨~⑫ `index.ts`

- **jev 失败不再中断流程**：`brief` / `qa` / `calibrate` 的三处 jev 调用全部 try/catch；
  失败时 triage 降级 `heuristic`、lint 返回空违规、verification 置 `unavailable`、
  `calibrate` 返回明确错误——与「失败自动降级」的设计承诺一致。
- **`calibrate op=sample` 未读为 0 时回退全库随机采样**（commit 之后全库已读会导致空样本）。
- **JSON 信封 `text`** + `markread` 文案优先用信封文本。
- **类型整理**：抽出 `TriageResult`，lint/verification 降级值用
  `Awaited<ReturnType<…>>` 对齐。

## 2. 回归测试（`tests/smoke.py`：26 → 31 项）

新增 5 项：
1. facts 区插入 `**国际经济**` 与 `### 科技`，断言 `stats.facts == 2`、`continuations == 1`；
2. 断言台账没有 `**` / `#` 开头的标题行；

- `tsc` 严格模式 0 错误；
- 额外手工验证：散文行报 `structure` 违规；`_split_trend` 在真实句式上解析出
  `signal=美债收益率`、`window=两周内`，解析不到时留空。

## 3. 真机效果（审核数据，供对照）

- 真实报告回放：`10-01_08.md` facts 34 → 30；台账无标题污染。
- 彩排（88 条已读临时改未读走完整三步）：144 s，jev 88/88 标注，
  skip 3 条高置信丢弃，qa 核验 3/4，commit 12 条（9 速览 + 3 观点），本批 88/88 重新标已读。
- 隔离测量（同 88 条、台账预热）：66 s；主模型 4 轮 / 3 次工具调用；
  prompt 82,447（in 25,487 + cacheRead 56,960）、输出 9,380；
  jev 约 21 次调用；观点 relation：强化 7 / 新出现 3 / 无变化 1（剔除）/ uncertain 2；
  事实 repeat_of 9。
- 新旧对比：轮次 16→4、工具调用 21→3、prompt 6.3× 少、成本 ≈ 2.2× 省。

**边界**（v0.5 起就存在，非本次修复项）：
- jev 没有压缩单次输入体积（payload ≈16k token > 旧 unread ≈12.4k token），
  省的是「轮次 × 重复上下文」与主模型的机械判断；
- codemode 在标准运行中不参与（扩展内代码调 jev），保留为逃生舱；
- 冷启动第一期台账为空，「延续」匹配不到时按设计不入台账。
